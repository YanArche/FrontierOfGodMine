# Развёртывание Frontier of God на Windows

Распакуйте Frontier-Server.zip в D:\FrontierServer. Корень содержит скрипты, server содержит мир и моды, data содержит окружение Python и data\production содержит SQLite и ключ cookie. Логи автозапуска пишутся в logs. Требуются локальный NTFS-диск, 64-разрядная Windows, Python 3.12 или 3.13 для выбранного пользователя, интернет для подготовки NeoForge и место для мира, обновлений и резервных копий. Java 21 включена.

## Первый запуск

1. Если на ПК уже есть сервер или рабочая база, штатно остановите старый экземпляр. Сделайте резервную копию мира, server.properties, ops.json, whitelist.json и всей папки рабочей базы, включая cookie.key и environment. Новая рабочая папка базы — D:\FrontierServer\data\production. При миграции перенесите туда рабочую папку базы до подготовки. Старые пути — %LOCALAPPDATA%\WoidWatchAccountHost\production и %ProgramData%\WoidWatchAccounts\data. Не переносите test.sqlite. Проверьте, что выбран именно действующий мир, а имя в level-name совпадает с его папкой.
2. Снимите метку загрузки с проверенного архива перед распаковкой или с отдельных доверенных скриптов после распаковки. Создайте отдельного локального пользователя Windows без прав администратора для задачи. Дайте ему изменение D:\FrontierServer, администратору — полный доступ. Уберите доступ обычных пользователей к data, особенно к базе и cookie.key. Проверьте Python в PATH именно этого пользователя.
3. От имени пользователя сервера выполните Prepare-server.cmd. Он готовит базу, зависимости, моды и NeoForge. Если это чистая установка, владелец должен прочитать Minecraft EULA и лично подтвердить её, изменив eula=false на eula=true в server\eula.txt.
4. Откройте Start-server.cmd и дождитесь Done, затем проверьте http://127.0.0.1:8787/health. registration должно стать true. Останавливайте через Stop-server.cmd, затем дождитесь сохранения мира и завершения процесса. Отключите старую отдельную задачу аккаунтов, если она конкурирует за порт 8787.
5. В PowerShell с правами администратора выполните из корня сервера .\Install-Autostart.ps1 -Credential (Get-Credential). В окне введите данные выделенного пользователя Windows. Скрипт регистрирует задачу, которая стартует через 30 секунд после загрузки, без входа в Windows, и делает до трёх повторов при ошибке. Запустите задачу вручную для проверки, затем проверьте после согласованной перезагрузки. При питании от сети отключите сон, если сервер должен оставаться доступным.

## Подключение извне

- В существующем Cloudflare Tunnel направьте accounts.noboredgames.win на http://127.0.0.1:8787. Служба cloudflared должна запускаться автоматически. Проверьте HTTPS /health из другой сети. Порт 8787 оставьте доступным только на loopback.
- Minecraft использует отдельный TCP-маршрут до порта 25565. Обычный HTTPS-маршрут аккаунтов его не переносит. Используйте действующий игровой туннель или согласованный проброс порта, затем задайте внешний адрес в меню «Менеджер» лаунчера под владельцем репозитория. Оставьте RCON выключенным. Проверяйте, что online-mode=true.
- Приглашения на регистрацию выдаёт accounts\Create-invite.cmd. Игрокам нужна актуальная версия WoidWatch с вкладкой друзей. Для регистрации используйте рабочую среду, без флажка тестовой службы. Проверьте два аккаунта из разных сетей, заявку и приглашение друга, вход обоих и отказ неизвестной игровой сессии. Приглашение друга сообщает адрес, а право на вход проверяется по действующей сессии WoidWatch. Ретранслятор одиночных миров в этот выпуск не входит.

## Нагрузка и обслуживание

Стартовые настройки рассчитаны на 5 активных игроков с запасом до 15. Java получает 2 ГБ начального и до 6 ГБ максимального heap. Сервер использует view-distance=7 и simulation-distance=5. Для существующего server.properties пользовательские значения этих параметров сохраняются. Для хоста с 16 ГБ RAM стартуйте с этих значений. Если на хосте 8 ГБ, сначала измерьте свободную память Windows и фоновую нагрузку. Тяжёлый модпак может потребовать отдельный хост.

Во время теста в новом и уже сгенерированном районе измерьте TPS, MSPT, RAM, CPU и диск. Начните с нескольких игроков. При росте MSPT сначала проверяйте новую генерацию, сущности и механизмы Create. Если узкое место — дальность, пробуйте view-distance=6 и simulation-distance=4. Профилируйте до увеличения heap. Для постоянного мира можно запланировать ограниченную предгенерацию нужной области вне игрового времени. Не обещайте 15 стабильных игроков без замеров на этом ПК.

Обновление модпака проверяется при штатном запуске по индексу GitHub. Подготовленный локальный комплект может стартовать с -Offline. Служба аккаунтов и код запуска обновляются заменой серверного комплекта в остановленном состоянии. Перед обновлением делайте резервную копию мира, рабочей базы и настроек, храните копию вне D:. Не заменяйте существующую папку server простым удалением. Для диагностики проверяйте logs, server\logs\latest.log и server\frontier-neoforge.log. Регулярно проверяйте размер логов и резервных копий.
