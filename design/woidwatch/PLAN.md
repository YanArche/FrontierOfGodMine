# WoidWatch Launcher · план проекта

Первый путь игрока: создать профиль WoidWatch → привязать Minecraft Java → выбрать Frontier of God → играть. При действующих сессиях повторный запуск занимает одно нажатие. Макет открывается локально из index.html. На экране гардероба можно примерить свой PNG. Все примеры управления и приглашений работают только в памяти страницы.

## Что берём из прежней концепции

«Бездна, что наблюдает», разомкнутое око, космический чёрный #0A0A0F, антрацит #111118, бирюза #00E6D6, фиолетовый #7B2CBF. Частота 13,7 Гц становится графической деталью состояния связи. Для доступности исключаем стробирование; предусмотрим уменьшение движения. В библиотеке остаются эфиры сообщества, новости и главный запуск. Тёплый пейзаж принадлежит Фронтиру. Вторая сборка получит собственную обложку и отдельную папку. Актуальное написание бренда — WoidWatch.

## Границы компонентов

* **Настольное приложение** ведёт библиотеку, установки, учётные записи и гардероб. Для первого этапа переиспользуем имеющийся Java 21 установщик и проверки файлов. Предусмотреть безопасную передачу игровой сессии процессу и фильтрацию секретов в диагностике.
* **Мод WoidWatch для NeoForge** рисует скины, плащи, титулы и эмоции в мире, показывает приглашения во время игры. Один лаунчер не может отрисовать чужой комплект на другом клиенте. На сторонних клиентах оформление зависит от их поддержки. Собственную косметику и ассеты с подходящими правами вносим в каталог. Перенос покупок и моделей Essential возможен только при согласованном доступе к каталогу и правам.
* **Сервис WoidWatch** хранит UUID профилей, привязки, дружбу, блокировки, титулы и журнал модерации. Отдельное хранилище принимает PNG после проверки размеров, декодирования и повторного кодирования. Приватные сообщения, сессии и данные игроков принадлежат закрытой инфраструктуре. Для ретранслятора до публичной беты определить хостинг, лимиты трафика и стоимость.
* **Игровая идентичность** подтверждается через Minecraft Services; собственная регистрация даёт доступ к функциям сообщества независимо от покупки. Для сетевой игры сохраняется проверка подлинности Minecraft. Microsoft-токены остаются на устройстве, refresh-токены хранятся в Keychain или Credential Manager. API сообщества принимает только свои короткоживущие сессии. [Условия Minecraft](https://www.minecraft.net/en-us/eula) · [Возможности Essential](https://essential.gg/)

## Владелец, команда и титулы

Первым владельцем назначается подтверждённый аккаунт автора. При развёртывании оператор сверяет устойчивый идентификатор владельца GitHub-репозитория, подтверждение через OAuth и ключ доступа WoidWatch, затем выполняет одноразовую серверную привязку к UUID. Ссылка приглашения короткоживущая и одноразовая. Повторный bootstrap закрывается. Смена ника, первый вход на пустой сервер или значение в клиентском конфиге никогда не дают права владельца.

| Назначение | Разрешения |
|---|---|
| Владелец | Назначение администраторов, восстановление управления, просмотр аудита. Передача владения требует повторного подтверждения и уведомления. |
| Администратор | Управление каталогом, титулами и модераторами. Публикацию исполняемых обновлений отдельно утверждает сопровождающий релиза. |
| Модератор | Жалобы, ограничение общения и блокировки с причиной, сроком и журналом. |
| Олд, Ютубер, Стример | Видимый титул профиля и персонажа. Игрок выбирает один из выданных. Эти назначения дают только оформление. |

Каждое привилегированное действие проверяется на сервере. У владельца два независимых средства восстановления. Лимиты входа и приглашений, отзыв устройств, закрытые по умолчанию контакты и аудит выдачи прав входят в приёмку. В публичном Git отсутствуют ключи, резервные коды и база аккаунтов.

## Обновления через GitHub

Версии приложения и сборок выпускаются отдельно. Защищённый тег запускает сборку Windows/macOS, тесты и подпись. GitHub Releases хранит установщики, пакеты и подписанные метаданные. В загрузчик вшит открытый корневой ключ. Метаданные TUF связывают платформу, версию, длину и SHA-256, ограничивают срок действия и защищают от отката на устаревший выпуск. Подпись Windows и нотарификация macOS входят в подготовку публичного лаунчера. [Модель обновлений TUF](https://theupdateframework.io/docs/overview/)

Лаунчер проверяет обновления при открытии, загружает их в промежуточную папку, применяет после закрытия и проверяет успешный старт. При сбое возвращается локальная рабочая копия. Для сервера обновления применяются перед следующим штатным стартом. В тестах обязательно подменить архив, прервать загрузку, отозвать ключ, предложить устаревший манифест и проверить сохранность миров. На этапе дизайна рабочий выпуск v1.0.0 продолжает обслуживать пользователей.
